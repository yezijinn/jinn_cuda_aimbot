## Issue Tracker

### Fixed P0 Issues

**P0: Trigger zone direction** (`runtime/trigger_system.cpp:99-105`, `58-70`)  
Trigger judgment now correctly checks whether the detection frame center (crosshair) falls inside the target bounding box's inner trigger rectangle. Fixed per IMPLEMENTATION_SPEC.md §5.1.

**P0 (was P1): `key_delay_ms` start timing** (`runtime/trigger_system.cpp:128-153`)  
`key_delay_ms` now starts when the crosshair first enters the trigger zone, not when the hotkey is pressed. If the crosshair leaves the zone before the delay expires, the timer resets to Idle immediately. Fixed per IMPLEMENTATION_SPEC.md §5.2.

**P0 (was P1): `leftUp()` failure state reset** (`mouse/mouse.cpp:792-805`)  
`releaseMouse()` unconditionally clears `mouse_pressed` regardless of whether the `leftUp()` device call succeeded. Prevents ghost-press after reconnect. Fixed per IMPLEMENTATION_SPEC.md §7.3.

### Fixed P2 Issues

**P2: Non-WIN32 I/O silent success** (`mouse/KmboxAConnection.*`, `mouse/Makcu.*`, `mouse/MouseInput.cpp`)  
KmboxA/Makcu device operations now propagate underlying send success/failure through `bool` returns, and `MouseThread` no longer clears `mouse_pressed` after a failed `leftUp()`. Build verified. Hardware characterization still requires on-device testing.

### Open P2 Issues

**P2: Trigger state machine sync on target loss** (`runtime/trigger_system.cpp:107-123`, `182-205`)  
`Firing` phase continues only while `TriggerSystem::update()` is called. If `autoShoot` changes to false mid-cycle, `releaseMouse()` is called but `triggerSystem.resetAll()` runs only on `config.auto_shoot` state change. Specific scenarios needing coverage: target loss + autoShoot off, target loss + hotkey release, target loss + device disconnect.  
*Requires supplemental simulation testing.*
