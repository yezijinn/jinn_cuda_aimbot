## 1. 权限范围与后端规则

### 1.1 唯一支持的后端

**必须**仅支持 CUDA/TensorRT 推理后端。

- 不得保留、恢复或新增 DirectML（DML）构建路径、运行时回退或发行包。
- `CMakeLists.txt` 必须在 `AIMBOT_USE_CUDA=OFF` 时以 `FATAL_ERROR` 中止，`USE_CUDA` 宏必须无条件定义。
- 任何引用 DML 构建命令、DML 依赖项或 DML 运行时的文档和脚本，对当前产品不具约束力。

### 1.2 冲突文档标记

以下文档/脚本中涉及 DML 的内容已被本规范取代，不得依照其中 DML 相关指令执行：

## 2. 模型生命周期

### 2.1 引擎兼容性失败处理

当 TensorRT `.engine` 文件加载失败（版本不兼容、架构不匹配或文件损坏）时：

1. **必须**先重命名旧引擎文件，再尝试任何重建操作。
2. 重命名规则：保留原文件基础名，在扩展名前插入 `_old_<本地时间戳>`。

   示例：`model.engine` → `model_old_20260726_153045.engine`

   时间戳格式：`YYYYMMDD_HHMMSS`（本地时区）。

3. 重命名后，**必须**在同一目录寻找与原引擎同名（不含扩展名）的 `.onnx` 文件。
4. 若同名 `.onnx` 存在，则从该 `.onnx` 自动重建引擎；若不存在，**必须**向用户展示明确错误并阻止启动。
5. 不得静默删除旧引擎文件。

### 2.2 类别数量推断规则

程序**必须**从模型输出张量形状自动推断类别数（NC），不得依赖文件名或写死静态值。

- 推断结果 NC 必须满足 `1 ≤ NC ≤ 19`。
- 若推断结果不在此范围内，**必须**向用户展示包含实际推断值和允许范围的可读错误信息，并阻止程序启动。
- 不得允许 NC = 0 或 NC ≥ 20 的模型进入运行时。

### 2.3 废弃语义

- **不得**保留 `class_player`、`class_head` 特殊含义或任何头部/玩家合并分支逻辑。
- 瞄准点由 `aim_offset_x`/`aim_offset_y` 在目标框归一化坐标系中统一定义，适用于全部模块。

## 3. 类别系统

### 3.1 全局启用：硬上限

- 全局类别启用列表（`class_enabled[]`）是程序级硬上限（hard allow-list）。
- **不得**让全局禁用的类别参与目标选择、目标锁定、鼠标移动或自动扳机。
- 模型推断的类别总数（NC）决定有效类别索引范围；索引范围外的类别不存在。

### 3.2 配置文件局部子集

- 3 个热键配置文件（Profiles）各自维护一个局部类别子集，该子集**必须**是全局启用集合的子集，不得超出全局启用边界。
- 全局类别启用变化时，三个配置文件的局部子集**必须**自动重置以匹配新的全局集合；当全局集合非空时，每个配置文件至少保留一个已启用类别。

### 3.3 缺失/未声明类别配置的默认行为

- INI 文件中缺失的类别条目默认为**关闭**（不启用）。
- 不得从配置继承未显式声明为启用的类别。

### 3.4 目标参与条件

运行时目标必须同时满足以下条件才可参与任何后续操作：

```
全局 class_enabled[class_id] == true
&& 当前激活配置文件 localClassEnabled[class_id] == true
```

不满足上述条件的类别不参与目标选择、排序、锁定、鼠标移动或自动扳机计算。

## 4. 热键配置文件

### 4.1 数量与结构

**必须**恰好有 3 个热键配置文件槽（Slot 1、2、3），不得增减。

每个配置文件独立持有以下局部设置：

| 局部设置项 | 说明 |
|---|---|
| 检测置信度阈值 | confidence_threshold |
| NMS 阈值 | nms_threshold |
| 瞄准偏移 | aim_offset_x / aim_offset_y |
| 移动速度 | movement speed |
| 弹道预测 | prediction |
| 压枪参数 | recoil |
| 动态范围 | dynamic range |
| 类别子集 | local class filter |
| 扳机参数 | trigger 区域、时序 |

### 4.2 激活语义：按住生效

- 配置文件激活模式固定为**按住生效**：按下时该配置文件逻辑激活，松开即逻辑失活。
- 不得支持 Toggle 或锁定激活模式。

### 4.3 同时按下的确定性优先级

多个配置文件热键同时被按住时，**必须**按以下确定性规则选择唯一激活配置文件：

**Slot 1 > Slot 2 > Slot 3**（序号越小优先级越高，无例外）。

此规则不得依赖时间戳、按下顺序或任何不确定因素。

### 4.4 auto_aim 模式下的激活规则

当 `auto_aim` 启用时：

- **必须**忽略物理热键按下状态。
- **必须**选择一个逻辑上"持续激活"的配置文件用于连续瞄准和自动扳机操作。
- **目标契约**：无物理按键被按住时，以 Slot 1 作为基线激活配置文件。此规则是明确的设计契约，不是推测默认值。
- `auto_aim` 下的自动扳机**可以在没有任何物理热键被按下的情况下完整执行**，仅受扳机区域和停止规则约束（见第 5 节）。

## 5. 扳机几何与状态机

### 5.1 几何定义

- **检测帧中心 = 准心位置**：检测帧（detection frame）的像素中心是准心的逻辑坐标原点。
- **目标内部区域（trigger zone）**：以 `aim_offset_x/y` 为参考点，由 `trigger_rect`（归一化的内矩形参数）在目标框内部定义的矩形区域。
- **触发判断**：当检测帧中心（准心）落入目标内部区域时，触发条件成立。即"目标框的内部区域包含了准心"。

此为确认的设计意图。AGENTS.md §12 P0 条目描述的"区域判断方向错误"指的是当前代码与本规范不符，需要修复以符合本规范，而非本规范需要修改。

### 5.2 状态机

扳机状态机包含以下状态：

```
Idle → KeyDelay → PreFire → Firing → Cooldown → Idle
```

#### 状态转换规则

**Idle → KeyDelay**

条件（全部满足）：
- `globalTriggerEnabled == true`
- 当前激活配置文件的 `triggerEnabled == true`
- 存在满足类别条件的有效目标
- 准心首次进入目标内部区域（第一帧观察到）

**必须**是准心首次进入目标内部区域时才开始 `key_delay_ms` 计时，不得在热键按下时或无目标时开始计时。

**KeyDelay 中途退出**

若在 `key_delay_ms` 到期前准心离开目标内部区域，**必须**立即重置 delay 计时器并返回 Idle 状态，不得继续计时。

**KeyDelay → PreFire / Firing**

`key_delay_ms` 到期后，进入 PreFire（若有预开火逻辑）或直接 Firing。

**Firing**

- 执行 `leftDown()`。
- 持续跟踪准心是否仍在目标内部区域。
- 达到 `max_fire_duration`（若配置）或目标内部区域条件不再满足时，退出 Firing。

**Firing → Cooldown**

- 执行 `leftUp()`。
- 等待 `cooldown_ms` 后返回 Idle。

#### 状态重置事件

以下任一事件**必须**立即将状态机重置到 Idle 并释放逻辑鼠标按下状态：

- 激活配置文件切换
- `auto_aim` 状态变化
- `globalTriggerEnabled` 变为 false
- 当前配置文件的 `triggerEnabled` 变为 false
- 配置重载（见第 6 节）
- 输入设备断开（见第 7 节）

#### 关于目标跟踪和鼠标移动的说明

在 `auto_aim` 模式下，鼠标移动（目标跟踪）和自动扳机可以独立运行。满足扳机区域条件时，**不要求**鼠标移动正在进行才能触发自动扳机。若准心已在目标内部区域内（无论是否因移动到达），均可触发完整的扳机状态机流程。

## 6. 配置所有权与运行时安全

### 6.1 配置分层

| 配置层 | 归属 | 示例字段 |
|---|---|---|
| 全局配置 | 程序级，所有配置文件共享 | 模型路径、全局类别启用、全局 FOV、输入设备 |
| 配置文件局部配置 | 每个热键 Slot 独立 | 阈值、偏移、速度、预测、压枪、类别子集、扳机参数 |

### 6.2 Overlay 即时生效

Overlay 界面上的配置修改（滑块、复选框等）**必须**立即生效，不需要用户点击"保存"或重启程序。

### 6.3 线程安全快照

所有运行时消费者（瞄准循环、扳机系统、目标选择）**必须**使用不可变快照（immutable snapshot）读取配置，不得在运行循环中直接读取原始配置对象以避免数据竞争。

### 6.4 配置重载安全序列

配置重载（reload）**必须**按以下顺序执行：

1. 阻断新的输入处理（block new input）
2. 释放逻辑和物理鼠标按下状态（`leftUp()`，确保状态同步）
3. 重置扳机状态机至 Idle
4. 清除当前目标和跟踪器状态
5. 重建配置快照
6. 恢复输入处理

不得跳过或乱序上述步骤。

## 7. I/O 失败处理

### 7.1 无 Win32 自动回退

当配置的输入设备（Arduino、KmboxA、Makcu 等串口/USB 设备）发生 I/O 失败时，**不得**自动回退到 Win32 API 鼠标输入。硬件设备是受信任的本地输入源；回退行为违反设计意图。

### 7.2 失败时的逻辑状态重置

发生任何 I/O 失败（移动失败、按下失败、释放失败）时，**必须**首先执行逻辑鼠标状态重置（将 `mouse_pressed` 等逻辑状态标记为已释放），再尝试重连或重试。

不得让失败后的逻辑状态停留在"已按下"，以防重连后出现幽灵按下。

### 7.3 各操作失败行为定义

| 操作 | 失败时行为 |
|---|---|
| `move()` 失败 | 记录失败，不重试移动；不得修改逻辑按下状态 |
| `leftDown()` 失败 | 必须将逻辑 `mouse_pressed` 置为 false；不得假设按下已成功 |
| `leftUp()` 失败 | 必须将逻辑 `mouse_pressed` 置为 false；不得保持"已按下"状态 |

所有失败均须触发设备重连流程（而非静默忽略）。

## 8. GPU 直通捕获（D3D11/CUDA 直通路径）

### 8.1 优先级声明

GPU 直通捕获（D3D11 capture → CUDA 设备内存，零 CPU 拷贝）是核心性能目标。

### 8.2 当前状态

当前直通路径处于**禁用状态**，原因是存在多显卡（multi-adapter）不匹配风险，不安全的跨适配器互操作可能导致崩溃或数据损坏。**不得声称直通路径已安全实现**。

### 8.3 重新启用的前提条件

直通路径**仅在以下条件全部满足后才可重新启用**：

1. 运行时验证：捕获适配器（capture adapter）与 CUDA 设备（CUDA device）为同一物理 GPU。
2. 匹配验证通过后，启用直通路径。
3. 不匹配时，**必须**回落到 CPU 安全路径，并输出明确的诊断信息（日志 + 可选的 UI 提示）说明原因。
4. **不得**在适配器不匹配的情况下执行不安全的跨适配器内存互操作。

### 8.4 验收标准

直通路径重新启用需通过以下验收测试：

| 测试 | 判定标准 |
|---|---|
| 单 GPU 环境：捕获 + CUDA 同卡 | 直通路径激活，帧率稳定，无崩溃，1000 帧无内存错误 |
| 双 GPU 环境：捕获与 CUDA 不同卡 | 自动回落 CPU 路径，输出诊断信息，功能正常 |
| 设备拔插/驱动重置后 | 回落 CPU 路径或重新验证后恢复直通 |
| 压力测试 | 连续运行 10 分钟，GPU 内存无泄漏，帧延迟方差在基线 ±15% 内 |

## 9. 强制验证场景与实现顺序

### 9.1 优先实现顺序（P0 最高）

**P0：必须先于其他特性实现/修复**

1. 扳机区域判断修复：判断检测帧中心（准心）是否落入目标框的内部区域；不得将区域判断替换为目标中心、目标框边界或其他屏幕固定区域（修复 AGENTS.md §12 P0）。
2. `key_delay_ms` 计时起点修复：计时从准心首次进入目标内部区域开始，而非从热键按下时开始（修复 AGENTS.md §12 P1）。
3. I/O 失败时 `mouse_pressed` 状态重置：`leftUp()` 失败时必须将状态标记为已释放（修复 AGENTS.md §12 P1）。

**P1：次要但影响核心正确性**

4. 引擎兼容性失败 → 重命名 + ONNX 重建流程。
5. NC 范围校验（1..19），失败时阻止启动并展示用户可读错误。
6. 配置重载安全序列实现。
7. 移除 `class_player`/`class_head` 残留语义。

**P2：性能和完整性**

8. GPU 直通捕获适配器匹配验证与安全重新启用。
9. 全局类别变化时三个配置文件子集自动重置。
10. 线程安全配置快照机制。

### 9.2 强制验证场景

以下场景必须在对应实现完成后通过验证，方可视为该功能完成：

| 场景 ID | 描述 | 通过标准 |
|---|---|---|
| VS-01 | 准心在目标外部，target box 存在 | 不得触发扳机 |
| VS-02 | 准心移入目标内部区域 | key_delay_ms 从此刻开始计时 |
| VS-03 | key_delay_ms 计时中准心移出区域 | 计时重置，返回 Idle |
| VS-04 | key_delay_ms 到期后准心在区域内 | 执行 leftDown() |
| VS-05 | Firing 中准心离开区域 | 执行 leftUp()，进入 Cooldown |
| VS-06 | auto_aim 无物理热键按下 | Slot 1 逻辑激活，扳机正常工作 |
| VS-07 | Slot 1+2+3 同时按下 | 仅 Slot 1 激活 |
| VS-08 | 全局禁用某类别，该类别目标出现 | 不参与任何操作 |
| VS-09 | leftUp() 调用失败 | mouse_pressed 置为 false |
| VS-10 | .engine 不兼容 | 重命名为 _old_<timestamp>.engine，从 .onnx 重建 |
| VS-11 | NC 推断结果为 0 或 ≥ 20 | 用户可读错误，阻止启动 |
| VS-12 | 捕获适配器 ≠ CUDA 设备 | 回落 CPU 路径，输出诊断信息 |
